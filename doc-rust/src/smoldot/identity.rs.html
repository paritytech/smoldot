18//! Substrate-based chains make frequent use of asymmetric cryptography. The identity of a user,
19//! be it an account address, a validator, or else, consists of a public key (also sometimes known
20//! as a verification key). A user can prove their identity by generating a signature using the
21//! private key (also sometimes known as a signing key) corresponding to that public key.
22//!
23//! A private key and a public key consist of 32 bytes of data. This poses a problem when it comes
24//! to end user experience. It is common for (human) users to have to manually copy a private or
25//! public key (using a pencil or their keyboard), and making a mistake could have catastrophic
26//! outcomes. It would be unwise to display keys and ask users to input keys as, for example,
27//! hexadecimal, because it is easy to make a copying mistake.
28//!
29//! For this reason, Substrate defines a human-readable format for public keys, named SS58.
30//!
31//! This format does not mention which asymmetric cryptographic algorithm (e.g. ed25519 or sr25519)
32//! is used for the public key. This must be deduced from the context.
33//!
34//! ## Public keys (SS58)
35//!
36//! Examples:
37//!
38//! - `5GrwvaEF5zXb26Fz9rcQpDWS57CtERHpNehXCPcNoHGKutQY`
39//! - `12bzRJfh7arnnfPPUZHeJUaE62QLEwhK48QnH9LXeK2m1iZU`
40//!
41//! The format for public keys consists in:
42//!
43//! > `base58(concat(prefix, 32-bytes-public-key, checksum))`
44//!
45//! The prefix, also known as network identifier, also known as an address type is one or more
46//! bytes identifying which blockchain network the address corresponds to. This is used for
47//! UX-related purposes in order to prevent end users from using an address on a different
48//! blockchain than the one the address was generated for.
49//!
50//! A registry of existing network identifiers can be found
51//! [here](https://wiki.polkadot.network/docs/build-ss58-registry).
52//!
53//! The checksum is verified when the human-readable format is turned into a public key. Its
54//! presence guarantees that simple copying mistakes will be caught.
